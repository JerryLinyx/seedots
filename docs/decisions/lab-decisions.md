# Lab 决策记录

日期：2026-10-20 至 2026-10-22。最终设计以 [`tech-plan.md`](../tech-plan.md) §5、§8 为准，本文记录**为什么这样做、放弃了什么、验证到哪一步、还剩什么**。外部调研见 [`../research/lab-references.md`](../research/lab-references.md)。

本文合并了这些过程文档：
- 实验台可行性的四轮记录；
- 交互学习流程中的服务设计部分；
- Lab 接入方案；
- Lab 交付给 agent 的方案。

原稿没有提交过，本次整理时删除。

## 1. 结论

交互场从“两种组件 + 自由代码”改为**实验台优先**：

- **实验台（rig）**：12 个预制、可参数化的实验台，加一份纯数据的规格。
- **服务**：一个独立的 Node 服务负责检查规格、计算答案和观测值。
- **agent 的分工**：
  - 流水线 agent 和定制实验 agent 都先用实验台；
  - 实验台表达不了，定制实验才写代码；
  - Coach 回答“如果……会怎样”时，数字由实验台服务算出。

## 2. 决策

| # | 决定 | 理由 | 放弃的方案 | 状态 |
| --- | --- | --- | --- | --- |
| D1 | **规格是纯数据**：选实验台，加上参数（range / toggle / seg）、控件、配置（公式用场景表达式语言）、读数、任务、播放、数据记录、预测，以及可选的 3D `stage`。公式之外没有可执行代码 | 模型写数据比写代码可靠；闸门能给出可操作的报错，直接回喂重试；参考 WeduLab 的声明式配置 | 让模型写章节脚本（“L1.5”，借鉴 WeduLab 的生命周期模块）：表达力强，但要沙箱，失败面大 | 已实现 |
| D2 | **通用闸门**：<br>- 公式只读已知名字；<br>- 参数全量程上观测量有限；<br>- 预测的改动能产生可见变化，且答案在选项内；<br>- 任务一开始未完成，并且用现有控件能完成；<br>- 3D 呈现与实验台匹配 | 把“好实验”的底线写成代码，而不是写在提示词里 | 截图视觉审查（只保留给代码实验） | 已实现；10 个故意改坏的规格全部被拒 |
| D3 | **同一份 TypeScript 两处运行**（`packages/rigs`）：浏览器里画图，Node 服务里检查规格、算答案 | 旧 L1 用 Python 和 TS 各写一份表达式求值，靠对比保持一致；实验台的计算多（抽样、积分、拟合），再移植一份容易出错 | 用 Python 再实现一遍 | 已实现；服务用 Node 的类型剥离直接运行 `.ts` |
| D4 | **实验台做成独立服务**（`services/rigs`，端口 8002），而不只是一个库 | 事实只有一份实现：生成时的检查、存库的答案、Coach 的工具都调用同一个服务；服务纯计算、无状态，便于独立部署 | 在后端里通过子进程调用 | 已实现：接口 `healthz`、`rigs`、`rigs/{id}`、`stages`、`check`、`observe`、`sweep` |
| D5 | **12 个实验台按通用性设计**：<br>- 通用：function、stocks（任意微分方程）、sampling、iteration；<br>- 按学科：vectors、distribution、field、particle、optics、cross、sun、timeline | function 和 stocks 两个实验台覆盖了 6 个和 4 个学科，几乎所有“量随参数或时间变化”的概念都能表达；只在通用实验台表达不了时才加专用的 | 逐个主题手写实验室（WeduLab 的做法） | 已实现；57 个案例、8 个学科，案例专用代码为 0 行 |
| D6 | **3D 挂在实验台上**：<br>- 规格加一个 `stage` 字段，计算仍由实验台完成；<br>- three.js 自己实现，所有场景共用一条后处理链：GTAO → 辉光 → 输出 → 暗角颗粒；<br>- 帧时间超过 25 ms 时自动降级 | 3D 不改变事实和闸门；同一个实验台可以有多种呈现：particle 有导轨、单摆、弹簧、抛体 4 种，地形视图同时用于地理和机器学习 | 照搬 WeduLab 的场景（版权）；只做 2D | 已实现 7 种视图；`lib/lab3d` 留在 `apps/web`，没有拆成包 |
| D7 | **流水线实验由 `lab_spec` agent 生成**：<br>- 用工具 `list_rigs`、`describe_rig`、`try_rig` 先试再交；<br>- 交答案后，服务端再复核一次；<br>- 答案只存服务端；<br>- 实验台服务不可用时，退回旧的两组件路径 | 让模型对照真实报错修改，而不是一次性生成；答案不经过模型，也不下发 | 一次生成 + 失败重来 | 已实现；每章最多 1 个实验（方案里提过 2 个，未做） |
| D8 | **命名先只改界面和新任务**：<br>- 区块标题改为 Lab；<br>- 标签按活动类型显示；<br>- 新的 agent 任务叫 `lab_spec`；<br>- 表、接口、事件和包名里的 `scene` 暂不改 | 完整改名涉及表、接口、事件、包、提示词、前端组件，是纯重构，不影响功能，可以单独做 | 一次性全仓改名（见第 5 节 B1） | 部分 |
| D9 | **定制实验 agent 自己选路线**：<br>- 先试实验台，最多两次 `try_rig`；<br>- 表达不了才写代码；<br>- 答案写明路线和理由，存在 `gates.route` | 实验台更快、更稳，也不需要截图审查；代码路线保留，用来覆盖长尾需求 | 学习者自己选“模板 / 代码” | 已实现；路线选择没有做真实模型评测 |
| D10 | **能力交付给 agent 的三种形态**：<br>- 目录卡片：何时用、何时不用、字段、观测量、示例，测试保证示例能通过闸门；<br>- 工具：按任务白名单发放；<br>- 沙箱 SDK：写代码时也能用实验台积木 | 每个 agent 只拿它需要的能力；卡片和实现放在一起，不会过时 | 把实验台说明手写进提示词 | 前两种已实现；沙箱 SDK 未做 |
| D11 | **Coach 用 `observe_lab` 和 `sweep_lab` 回答“如果……会怎样”**：<br>- 模型只能写实验编号，拿不到也改不了规格；<br>- 回答里用 `[Try it in the lab](#lab-<id>?param=v)` 链接打开实验 | 落实“事实由代码算”。用链接而不是新增 `open_lab` 工具：前端渲染成按钮，不需要多一轮工具调用 | `open_lab` 工具 | 已实现；没有做真实模型评测 |
| D12 | **动作选择新增 `lab`**：只在章节末尾触发，只从本章已就绪的实验里挑，不在线生成 | 不打断观看；遵守“在线只查表”；迁移 `0003` | 在长停顿、反复回看时推荐 | 已实现 |
| D13 | **定制实验的构建过程实时推送**（SSE）：<br>- 网关 `run(on_event=...)` 把思考、写参数、工具调用和结果翻译成学习者看得懂的步骤；<br>- 草稿一通过实验台检查就推送，可以先试 | 构建要 1–1.5 分钟，原来只能等进度条 | 轮询粗粒度的 `progress` | 已实现；推送只在进程内有效，换成远程 worker 后退回轮询 |
| D14 | **定制实验的答案用 JSON 文本交**（prompted），不用工具调用：<br>- 解析放宽，字符串形式的规格也接受；<br>- 答案里没有规格时，采用最后一份通过检查的稿子 | 真实模型常常用文本作答，工具模式下重试耗尽而失败（“Exceeded maximum output retries”） | 工具模式 + 加大重试次数 | 已实现 |

## 6. 已知限制

- **历史学科最弱**：时间线只展示证据里给出的数据；叙事型交互（沙盘、疆域变迁）没有对应的实验台。
- **物理是简化版**：只有单质点运动和几何光学。
- **生物过程**表达不了：细胞结构、免疫动画、显微镜操作。
- **定制实验的构建推送**只在进程内引擎下可用。
